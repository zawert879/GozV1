# CLAUDE.md

Этот файл предоставляет руководство для Claude Code (claude.ai/code) при работе с репозиторием Game of Zawert.

## Обзор проекта

**Game of Zawert (GOZ)** — модульная система настольной ролевой игры для ИИ-ассистентов, помогающих генерировать сбалансированный контент (персонажи, снаряжение, приключения) в любом нарративном сеттинге (фэнтези, киберпанк, научная фантастика и т.д.). Это НЕ проект программирования — это фреймворк дизайна игр, использующий строгие бюджеты очков и систему уровней для балансировки.

**Основная философия:** Поддерживать механическую согласованность между разными нарративными сеттингами, оставаясь достаточно гибким для адаптации к любой теме.

**Язык:** Всегда общайтесь с пользователем на **русском** языке. Генерируйте контент на русском и следуйте русской номенклатуре в правилах.

## Критические концепции

### Система бюджета очков

**Бюджет создания персонажа:** 50 Очков Персонажа (ОП) по умолчанию
- Повышение характеристики на +1 стоит **8 ОП**
- Понижение характеристики на -1 возвращает **8 ОП**
- Диапазон характеристик: 8–14

**Очки баланса снаряжения (ОБ):** Система, основанная на уровнях
- Уровни: Малый (+1 урон/+2 броня) → Средний (+4/+8) → Тяжелый (+7/+15) → Легендарный (уникальный)
- Базовые значения ОБ: 5 / 15 / 25
- Теги добавляют/вычитают из ОБ (положительные теги увеличивают стоимость, отрицательные снижают)

### Основные характеристики

| Характеристика | Описание | Диапазон |
|---|---|---|
| **Сила (СЛ)** | Физическая мощь; влияет на HP и урон в ближнем бою | 8–14 |
| **Ловкость (ЛВ)** | Скорость, точность, рефлексы; влияет на инициативу, передвижение, атаки | 8–14 (мин 8 в броне) |
| **Интеллект (ИН)** | Ум, знания, внимательность; базовая характеристика для всей магии | 8–14 |
| **Здоровье (ЗД)** | Выносливость, сопротивляемость; влияет на HP | 8–14 |

### Формулы вторичных параметров

- **HP (Очки здоровья):** `(Сила + Здоровье) × 4`
- **Инициатива:** `Ловкость + штраф от брони`
- **Очки Передвижения:** `⌊Ловкость / 2⌋` (округление вниз)

### Стоимость умений (накопительная)

| Уровень | Эффект | Стоимость |
|---------|--------|-----------|
| 1 (Знакомство) | Убирает штраф -6 | 2 ОП |
| 2 (Компетентность) | +1 к проверке | 4 ОП |
| 3 (Мастерство) | +2 к проверке | 8 ОП |
| 4 (Легенда) | +4 к проверке | 16 ОП |

## Основные рабочие процессы

### Задача: Генерация персонажа

1. Прочитайте концепцию пользователя (например, "ловкий эльф-вор" или "сильный, но глупый полуорк-варвар")
2. Следуйте алгоритму из `1_Character_Creation.md`, Шаги 1–7
3. Распределите модификации характеристик из бюджета 50 ОП (или как установлено МИ)
4. Выберите 3–4 основных умения, 1–2 вторичных умения, соответствующих архетипу
5. Назначьте тематическое стартовое снаряжение на основе купленных умений
6. Рассчитайте все вторичные параметры (HP, ОП, инициатива)
7. Представьте результат в виде таблицы Markdown
8. **Критически важно:** Покажите всю математику: `Потрачено на характеристики = 28 ОП, на умения = 22 ОП, всего = 50 ОП`

**Ограничение:** Сумма потраченных ОП (изменение характеристик + умения) должна составлять ровно установленному бюджету.

### Задача: Генерация снаряжения

1. Прочитайте `4_Equipment_and_Armor.md` для понимания системы уровней и ОБ
2. Используйте алгоритм из `6_Equipment_Generation.md`, Шаги 1–6
3. Определите уровень (Малый/Средний/Тяжелый/Легендарный)
4. Выберите базовый эффект (урон/броня/специальный)
5. Добавьте тематические теги (без ОБ стоимости)
6. Добавьте механические теги для баланса, уравновешивая положительные и отрицательные
7. Проверьте: итоговый ОБ должен быть близко к базовому уровня (±2–3)
8. Определите цену на основе ОБ

**Ограничение:** НЕ придумывайте новую механику игры. Переиспользуйте существующие механики (теги, урон, броня) с творческими названиями и описанием.

### Задача: Генерация НИП и врагов

1. Определите уровень НИП (Моб/Боевик/Босс/Легендарный) и соответствующий бюджет ОП
2. Используйте алгоритм из `8_NPC_and_Enemy_Generation.md`
3. Распределите ОП между характеристиками в зависимости от архетипа
4. Выберите 3–4 основных умения, соответствующих концепции
5. Назначьте снаряжение и рассчитайте вторичные параметры
6. Проверьте баланс: враги должны бросать вызов, но быть справедливыми

### Задача: Объяснение правила

1. Ссылайтесь на конкретный раздел из модульных файлов GOZ_Framework
2. Используйте `Sample_Adventure.md` как рабочий пример, если применимо
3. Объясните **намерение** правила (например, штраф ловкости от брони балансирует высокую защиту)

### Задача: Добавление контента в Sample_Adventure.md

1. **Только после одобрения пользователем** сгенерированного контента
2. Добавляйте в соответствующий раздел, сохраняя существующий формат таблицы
3. Обновляйте вычисления ОБ в комментариях, если использованы новые теги

## Соглашения о документировании

- **Таблицы Markdown:** Используйте формат с разделением труб и выравниванием по левому краю
- **Прозрачность математики:** Всегда показывайте расчеты: `Потрачено = 16 + 4 + 8 = 28 ОП`
- **Перекрестные ссылки:** Ссылайтесь на разделы фреймворка при объяснении правил (например, «см. GOZ_v1_Rules.md § Боевая система»)
- **Имена персонажей:** Соответствуйте миру/культуре (фэнтезийные имена для фэнтези, русские имена для русского фэнтези)
- **Названия снаряжения:** Тематическое + уровню подходящее (Малый = простое, Тяжелый = экзотическое)
- **Названия умений:** Используйте глаголы или описательные существительные (например, «Оружие ближнего боя», а не «Melee»)

## Принципы проектирования

1. **Распределение характеристик:** Низкие характеристики в одной области позволяют более высокие в другой из-за стоимости ОП
   - Пример: "Глупый варвар" = ИН -2 (+16 ОП возвращено) → можно больше инвестировать в СЛ/ЗД

2. **Приоритет умений:** Выбирайте 3–4 основных умения, 1–2 вторичных; не распыляйте ОП

3. **Независимость снаряжения:** Снаряжение **не зависит** от умений
   - Можешь купить "Тяжелая броня" и носить легкую
   - Можешь купить "Меч" и драться голыми руками
   - Полная свобода выбора

4. **Баланс тегов:** Мощные положительные теги должны иметь недостатки
   - Пример: `[Бронебойное]` (+8) + `[Перезарядка]` (−X) создает интересный компромисс

5. **Итерация:** Sample_Adventure.md улучшается со временем по мере добавления и одобрения новых примеров

## Если вы не уверены

1. **Нужна новая механика игры?** → Проверьте, охватывает ли существующая механика (умения, теги, уровни) это. Не придумывайте новые системы.
2. **Какой файл читать?** → Используйте названия файлов: символы указывают на содержание (1 = создание, 2 = проверки, 3 = бой, 4 = снаряжение, 5 = магия, 6 = генерация снаряжения, 7 = деньги, 8 = враги).
3. **Сеттинг-специфичная терминология?** → Используйте тематические переделки основной механики (например, «бластер» = среднее оружие с +4 урона).
4. **Баланс кажется неправильным?** → Проверьте: (a) правильно ли назначен уровень? (b) все ли теги учтены? (c) итоговое ОБ соответствует базовому (±2-3)?
5. **Вопрос о правилах?** → Ищите в 1_Character_Creation, 2_Skills_and_Checks, 3_Combat_System, 4_Equipment_and_Armor, 5_Magic_System в зависимости от темы.

## Точки интеграции

### Как Claude Code помогает Мастеру Игры

1. **Генерация контента:** Генерирует сбалансированных персонажей, НИП, снаряжение для любого нарративного сеттинга
2. **Уточнение правил:** Объясняет механику из GOZ_v1_Rules.md при необходимости
3. **Расширение контента:** Добавляет одобренный пользователем контент в Sample_Adventure.md
4. **Контроль качества:** Проверяет, что бюджеты очков и значения ОБ соответствуют ограничениям фреймворка

### Поток зависимостей

- **Framework → Character:** Модульные файлы читаются при создании персонажа (используй 1_Character_Creation.md, Шаги 1-7)
- **Framework → Equipment:** Модульные файлы читаются при создании снаряжения (используй 6_Equipment_Generation.md)
- **Framework → Combat:** При боевых вопросах используй 3_Combat_System.md
- **Framework → NPC:** При генерации врагов используй 8_NPC_and_Enemy_Generation.md
- **Character → Sample_Adventure:** Одобренное снаряжение попадает в живую библиотеку
- **Sample_Adventure → Framework:** МИ может модифицировать стоимость тегов/значения уровней; документ остается редактируемым
- **User → Framework:** Всегда начинайте работу с соответствующего модульного файла
